# 아빠표 영어 공부

EBS 초등 영어 읽기 Unit 1~52를, 집에서 아이와 20분 안에 끝낼 수 있는 학습 자료로 만들어 둔 곳.
**52개 유닛 전부 자료가 준비되어 있다** — 읽기 페이지 52장, A4 문제지 52장(각 3쪽).

**주소** → https://themoka7.github.io/myChildrenEngStudy/

## 페이지 구성

| | 무엇 | 어디서 쓰나 |
|---|---|---|
| **지도** (`index.html`) | 52권이 테마별 구역으로 길에 늘어선 메인 화면. 한 권 끝내면 그 칸에 **도장**을 찍는다 | 아이가 보는 화면 |
| **읽기 페이지** | 단어에 손을 대면 품사·발음·뜻 툴팁, 문장마다 해석 토글과 🔊 듣기, 단어 퀴즈(4지선다) | 화면에서 눌러가며 |
| **A4 문제지** | 지문 + 6문항 2장(단어연결·파닉스·찾아쓰기·O/X·빈칸·따라쓰기) + 부모용 정답·지도 노트 1장 | 종이에 뽑아 연필로 |
| **목록** (`list.html`) | 학습 날짜·걸린 시간·상태 필터가 있는 표 | 부모용 |

지도에서 칸을 누르면 「읽으러 가기 · 문제지 뽑기 · 도장 쾅! 찍기」가 뜬다.
읽기 페이지는 기본적으로 해석이 숨어 있다 — **먼저 영어로 읽고, 막힐 때만 펼치는** 순서를 의도한 것이다.
날짜·시간이 필요한 관리용 표는 지도 아래 「부모용 목록」으로 빼 두었다. 지도에 그걸 다 넣으면 아이 화면이 관리 화면이 된다.

### 도장은 어디에 저장되나

두 군데에서 온다.

- `units.json` 의 `status: "done"` → 지도에 **미리 찍혀 있는 도장**. 저장소의 기록이라 어느 기기에서 열어도 같다.
- 브라우저 `localStorage` → 아이가 **직접 찍은 도장**. 그 기기에만 남는다.

저장할 때 그때의 씨앗 목록을 함께 남겨 두고, 다음에 열 때 **그 사이 새로 완료로 바뀐 것만** 더한다.
그래서 `units.json` 을 나중에 고쳐도 아이가 일부러 뺀 도장이 되살아나지 않는다.

기기가 바뀌면 도장은 따라가지 않는다. 지도 아래 **「진도 복사하기」** 로 완료 목록을 뽑아 `units.json` 의
`status` 에 옮겨 적으면 그때부터 어디서 열어도 같아진다.

## 인쇄

A4 문제지에서 `Ctrl+P`(맥은 `⌘+P`) → 배율 100% → **「배경 그래픽」 켜기**.
정답지를 빼고 뽑으려면 페이지 위쪽의 「정답지 빼고 인쇄」를 체크한다.

## 유닛 추가하기

지문은 손으로 넣고, HTML은 전부 생성물이다. 직접 고치지 말 것 — 다시 빌드하면 덮어쓴다.

```
data/unitNN.read.json    읽기 페이지용 — 문장별 해석 + 핵심 단어 사전
data/unitNN.quiz.json    A4 문제지용 — 6문항
```

두 파일을 만든 뒤:

```bash
python3 tools/build_unit.py NN     # read/unitNN.html + print/unitNN.html
python3 tools/build_map.py         # 메인 지도(index.html) 다시 생성
python3 tools/build_index.py       # 부모용 목록(list.html) 다시 생성
```

그리고 `units.json` 에서 그 유닛에 `"ready": true` 를 붙이면 지도에서 점선으로 비활성이던 칸이 눌리게 된다.
아이가 누를 칸의 그림은 같은 파일의 `"ico"` 다.

두 JSON의 스키마는 각 스킬 문서에 있다 (`eng-make-question`, `english-reading-html`).
`build_unit.py` 는 기본적으로 `~/.claude/skills/synced` 에서 두 스킬의 빌더를 찾는다. 다른 곳에 있으면 `--skills` 로 알려준다.

### 데이터 전수 검사

```bash
python3 tools/check_data.py
```

빌더가 잡아 주지 않거나 경고로만 넘기는 것들을 오류로 세운다 — 파닉스 단어가 자기 지문에 없는지(아이가 답을 확인할 수 없게 된다), 빈칸 정답이 보기에 없는지, 인용한 문장 번호가 지문 범위를 벗어나는지, O/X가 한쪽으로 몰렸는지(전부 O면 읽지 않고도 만점이다), 지도·목록·출력 링크가 깨졌는지, 정답지 워밍업 줄이 그 유닛의 ②번 단어를 가리키는지. 유닛을 추가한 뒤 커밋 전에 돌린다.

### A4가 3쪽을 넘칠 때

`build_unit.py` 는 문제지를 만들 때 실제로 렌더링해서 **3쪽인지, 잘린 곳이 없는지** 검사하고, 넘치면 실패로 멈춘다.
A4 문제지의 `.page` 는 높이 고정 + `overflow:hidden` 이라 **넘친 내용이 쪽수를 늘리지 않고 조용히 사라지기 때문**에 이 검사를 건너뛰면 안 된다.

어느 쪽이 넘치는지는 `python3 tools/where_overflow.py print/unitNN.html` 로 짚어 준다.

넘쳤을 때는 문항을 하나 덜어내면 대개 해결된다. 덜어낼 순서 —
③(찾아 쓰기)은 이 워크시트의 핵심이라 마지막까지 남기고, **다른 문항과 단어가 겹치는 항목부터** 뺀다.
Unit 1이 실제로 그랬다: ⑤ 빈칸의 `fast` 가 ②·③과 겹쳐 그걸 빼고, ⑥ 따라쓰기 한 문장을 지문 후반부 문장으로 바꿨다.

## 배포

`main` 또는 `claude/**` 브랜치에 푸시하면 GitHub Actions가 저장소를 그대로 Pages에 올린다 (`.github/workflows/pages.yml`).

**Pages는 저장소 설정에서 한 번 켜 줘야 한다** — Settings → Pages → Build and deployment → Source를 `GitHub Actions`로. 워크플로에 `configure-pages`의 `enablement: true`가 들어 있지만, 워크플로 토큰으로는 Pages를 처음 켤 권한이 없어 `Resource not accessible by integration`으로 실패한다. 한 번 켜 두면 그 뒤 배포는 전부 자동이다.

이 저장소는 첫 푸시가 `claude/skill-utilization-6jr45t` 였고 저장소가 비어 있었기 때문에 그 브랜치가 기본 브랜치로 잡혔다. Pages는 기본 브랜치에서만 배포되므로 결과적으로 맞아떨어졌지만, 브랜치 이름을 바꿀 때는 기본 브랜치 설정도 함께 옮겨야 한다.
